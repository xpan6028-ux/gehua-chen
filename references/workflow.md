# 从用户问题到可复现操作

按任务需要采用以下环节，不强制给每位用户填长表。

## 先确认什么

收集y、受检验x、始终保留的控制变量、可枚举候选池、估计器、固定效应、标准误、样本范围及输出位置。面板任务还需id与时间变量、处理变量的定义。用户给出可运行基准模型时，从该模型提取这些角色并与用户的研究目的核对。

把“我要学习视频命令”“我想检查规格敏感性”“我只想找显著结果”区分开。解释命令真实行为；涉及研究结论时说明选择结果带来的解释限制，不改写用户原始数据来迎合符号或显著性。

## 环境检查

```stata
display c(stata_version)
display c(flavor)
which oneclick
help oneclick
viewsource oneclick.ado
```

安装命令是`ssc install oneclick`；已有安装是否更新，由当前任务及版本要求决定。需要`reghdfe`时另外核对其安装与依赖。安装过程改变用户Stata环境，仅在用户要求安装或已授权的执行任务确实需要时进行。

无法运行Stata时，区分“源码核验”“代码静态检查”“Stata执行成功”三个状态，交付可运行代码而不虚构日志。

## 运行前预检

1. 确认变量存在、类型适合，x不与候选池重复，固定保留项与候选池不重复；原版要求至少2个候选，本技能全规格扩展可从0个候选开始。
2. 先单独运行一条目标估计器回归，核对x可估计且标准误有效，检查`e(df_r)`/实际统计量与是否需要z。
3. 检查数据中是否已有`subset direction coef p r2`；原版会生成同名字段。对用户字段不直接删除，先保留原数据、在明确的工作副本中处理并记录映射。
4. 计算模型规模。k个候选至少有指数级组合生成开销；预算工具见`../scripts/model_budget.py`。根据实际单次估计耗时、样本规模、可用内存与允许时长决定是否缩小理论上合理的候选池。不能仅凭视频“提速”承诺秒级结束。
5. 明确样本策略。不同候选的缺失值会造成不同估计样本，原版不自动锁定同一`e(sample)`。需要共同样本比较时，应先按相关变量建立明确的共同样本；同时说明样本缩小及潜在选择影响。
6. 创建或使用本次专用输出目录；默认文件会覆盖，失败后旧文件可能留下。记录运行前文件状态，使用新文件名，确保运行后确实产生新结果。

原版不接受顶层`if`/`in`/weights。样本范围应在受保护的工作副本中预先处理，或改用单独编写的循环；不能把不支持的语法直接拼到`oneclick`上。

预算脚本需要真实可用的Python3解释器；Windows的`python`可能只是商店占位入口，遇到这种情况先查实际解释器路径。没有Python时，可依 [实现审查](implementation.md) 中的组合公式计算预算，技能的命令讲解与代码生成仍可使用。

## 执行与观察

执行时记录软件和包版本、完整命令、固定样本规则、候选池、阈值、运行时间与返回码。面对估计失败或全部无匹配组合，不自动换样本、变量、标准误或阈值直到成功；先检查日志与基准回归。

原版会捕获部分回归错误并最终删去相应错误行。因此“程序跑完”不表示每个规格成功。其结果文件也没有完整的失败数和失败原因；若这对任务重要，采用[扩展执行器](execution.md)的fullspec入口。

## 运行后怎么核验

- 文件是否本次新生成？无匹配时是否错误读取了旧结果？
- 列名与本版本一致吗？`full`输出的是`command`还是`subset`？
- 每一行的受检验变量、固定效应与标准误是否符合原设计？
- 至少重跑一条选中规格，核对受检验系数、实际p值、N、SE、自由度和样本。
- 正/负组数、筛选阈值与实际重估能否对应？不要从星号反推出精确p。
- 需要比较结果分布时，是否还缺少未通过的规格与失败规格？原文件不能回答这一问题。

## 扩展到全规格记录

用户需要完整记录时，采用[执行器与全规格扩展](execution.md)的JSON配置，先生成计划并核对候选、样本与模型预算，再在授权范围内运行。它逐条记录编号、组合、命令、估计/推断状态、N、b、SE、原生双侧p和拟合度；失败及不显著规格不会被丢弃。

这种循环是本技能新增且经过教学/合成数据实测的扩展，不是原版OneClick已有输出。共同完整案例输入池仍可能被估计器进一步删样本，检查实际样本字段。规格曲线、跨规格样本成员比较及识别有效性审查未由执行器自动完成。
