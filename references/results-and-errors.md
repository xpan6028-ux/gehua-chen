# 输出解读与排错

## 6.0实际输出

默认文件名是`oneclick_subset.dta`，指定`saveplace()`则使用指定文件，均以`replace`保存。官方帮助的Results段仍提到旧文件名与旧字段；这里按本次源码区分。

| 字段 | 实际含义 | 常见误读 |
| --- | --- | --- |
| `subset` | 通过筛选的非空候选组合 | 不是整个控制变量集合，固定项不在其中 |
| `command` | 设置`full`后替代`subset`的完整回归命令 | `full`没有增加未通过筛选的规格 |
| `direction` | 1为受检验系数正向，0为负向 | 不是因果方向已成立的证明，也没有预设方向过滤 |
| `coef` | `fixvar()`第一项的系数 | 不是所有解释变量的系数 |
| `p` | 字符串星号 | 不是数值p值，不能做`p<.05`等比较 |
| `r2` | 源码记录的`e(r2)` | 不保证所有估计器都返回；不是调整R²，也未解决不同样本比较问题 |

文件未保留N、SE、自由度、精确p值及失败原因。需要这些信息时重估或新写完整循环；不得从没有的列中补造。

源码星号规则使用严格不等号：介于.05与.1之间为一颗，介于.01与.05之间为两颗，小于.01为三颗。恰好等于.05或.01时可能没有星号；筛选阈值本身同样采用严格小于。因此“空星号”不够判断是否未通过，必须重估核对实际p值。筛选阈值与常见星号界限也不是同一个概念。

## 报错与处理路径

| 现象 | 优先核对 | 不应直接作出的结论 |
| --- | --- | --- |
| `oneclick`无法识别 | `which oneclick`、安装路径、包是否已安装 | 不是数据或研究假设出了问题 |
| 版本参数不支持 | `viewsource oneclick.ado`与本地help，是否旧版/同名文件抢先加载 | 不能因为视频叫6.0就认定本机是6.0 |
| 变量数不够 | 逗号前是否y加至少两个候选 | 不能靠把x移入候选池凑数 |
| 已存在`subset`等同名字段 | 原版工作列与数据字段冲突 | 不直接删除用户字段后继续运行 |
| 路径或写入失败 | 结果目录、权限、磁盘和文件占用；选用户可写的新目录 | 不自动提升系统权限或改全局目录 |
| 系数、标准误提取失败 | 基准回归中x是否被省略、系数名是否匹配、估计器是否返回字段 | 不直接改动解释变量的含义 |
| 自由度或局部p值失败 | 是否需要`zvalue`，估计器输出何种统计量 | 不把z当作万能修复选项 |
| 运行非常慢/内存增大 | 候选数量、2^k中间行数、样本、估计器耗时 | `threshold`不保证消除指数开销 |
| 屏幕有显著组但字段不像帮助 | 本次6.0源码与帮助中的旧说明差异 | 不把方向列强行重命名成旧版语义来掩盖差异 |
| 全部没有匹配，返回`error 1` | 先查基准回归、阈值、候选池、分布设定及估计失败 | 不等于程序坏了，不等于效应已证明为零，也不保证必能筛到 |
| 失败后目录仍有结果文件 | 文件修改时间和本次新文件名；是否是前次残留 | 旧文件存在不等于本次成功 |
| `best`选中奇怪规格 | `r2`缺失、样本变化、R²只是拟合度 | 不叫“最优因果模型” |

报错代码依Stata环境与估计器可能不同。没有真实日志时，上表只是诊断路径，不声称确定某个返回码只有一种原因。

## 怎样向用户报告

分别给出“已观察到”“候选解释”“下一步检查”。真实执行报告包含返回码、输出文件时间与路径、实际列名、重估核对结果；没有执行时明确写“静态检查”。

只有筛选后结果时，可以解释其中变量组合、符号和系数，不能计算全部规格显著比例，也不能声称不显著结果不存在。筛选输出不能独立证明稳健性；若要完整规格分布，读取全部规格的单独日志。
